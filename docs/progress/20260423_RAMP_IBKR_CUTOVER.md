# RAMP IBKR Cutover - 2026-04-22 / 2026-04-23

## Summary
`homeguard-multi` had been crash-looping since 2026-04-15 after a `broker_name` kwarg change in `OMRLiveAdapter`/`RAMPLiveAdapter` was not propagated to `run_multi_strategy_streaming.py`. Five consecutive RAMP rebalances (Apr 15 PM, 16, 17, 20, 21) silently produced zero orders. Investigating surfaced a sequence of bugs that masked each other: BRK.B/BF.B symbol-format mismatch on IBKR, a RAMP historical-data path that reached through `self.broker` (= IBKR after the routing cut-over, not Alpaca), a streaming→REST fallback with an indentation bug that made it dead code, and a cache-freshness check that trusted a today-row even when mostly NaN. A forensic look at the Thu 04-23 rebalance also revealed a separately dormant bug: `PortfolioHealthChecker.check_before_entry` calls `broker.get_open_orders()` which `IBKRBroker` never implemented — blocking entry even when every other piece of the rebalance worked.

## Changes Made
- **`infra/ec2/homeguard-multi.service`**: ExecStart swapped from the pre-migration `run_multi_strategy_streaming.py` to `run_live_paper_trading.py --strategy ramp`. The old script hardcoded `AlpacaBroker` and ignored `broker_routing.yaml` / `strategy_toggle.yaml`; the new one reads both. User follow-up added `ExecStartPre` that waits for IBKR Gateway to bind port 4002 (up to 120s), `ENABLE_METRICS=true`/`METRICS_PORT=8082` env vars, and `SyslogIdentifier=homeguard-multi`.
- **`src/trading/brokers/ibkr/symbols.py`** (new): regex-gated `to_ibkr_symbol` / `from_ibkr_symbol` for multi-class share tickers (`BRK.B` ↔ `BRK B`, `BF.B` ↔ `BF B`). Pattern tight enough to pass through `AAPL`, `SPY`, `V`, etc. unchanged.
- **`src/trading/brokers/ibkr/contracts.py`**: `resolve_stock` normalizes inbound symbol before constructing the IB `Stock()` contract. `_qualify` now raises `SymbolNotFoundError` on `[None]` (ambiguous-contract) in addition to empty — without this, 7 S&P 500 symbols (MMC, FI, K, HOLX, DAY, WBA, IPG) crashed with `AttributeError` instead of being handled gracefully.
- **`src/trading/brokers/ibkr/ibkr_broker.py`**: `_translate_stock_position`, `_translate_order`, `_translate_option_position` reverse-normalize `pos.contract.symbol` before returning to strategy code, so `BRK B` from IB becomes `BRK.B` for the state manager's cross-broker preflight. User follow-up: `get_account` now uses `accountSummaryAsync` (idempotent) instead of `reqAccountSummaryAsync`, fixing IBKR error 322 "Maximum number of account summary requests exceeded" after the first per-tick call.
- **`src/streaming/alpaca_market_data.py`** (new): `AlpacaMarketData` composes `AlpacaDataProvider` (REST historical via a dedicated data-only `AlpacaBroker`) + `LiveDataProvider` (WebSocket streaming). Implements `StreamingProviderInterface` so RAMP's `isinstance` check still passes, and adds `get_historical_bars` / `get_historical_bars_batch` so historical data no longer falls back to the execution broker. Encodes the user's invariant: Alpaca for all data, IBKR for all execution/portfolio.
- **`src/trading/adapters/ramp_live_adapter.py`**:
  - `preload_historical_data` routes through `self._data_provider` when it exposes `get_historical_bars`, with SPY also going through the same source. Also drops any today-row with <80% valid cells before persisting to disk — prevents the 09:31 AM market-open preload from poisoning the cache with a near-empty today-row.
  - New `_pick_rest_source()` helper: prefer `self._data_provider` for REST; fall back to `self.broker` only when no data provider is configured.
  - `fetch_todays_closes` restructured: streaming attempted first, then REST fallback via `_pick_rest_source` when streaming returns <50% valid. Fixed the long-standing indentation bug where the "fall back to broker API" branch was attached to a success-rate check and therefore unreachable. Also added a validity gate — a cached today-row with <80% valid values is treated as missing and dropped before refetch, instead of silently trusted.
- **`src/trading/brokers/interfaces/order_management.py`**: added concrete default `get_open_orders()` that delegates to `get_orders(status=OrderStatus.PENDING)`. IBKRBroker missing this method was the final reason the Thu 04-23 rebalance placed 0 orders despite preload / signal gen / quote fetches all working.
- **`scripts/trading/run_live_paper_trading.py`**: streaming path now constructs `AlpacaMarketData` instead of bare `LiveDataProvider`. No adapter API change.
- **`scripts/trading/validate_ibkr_sp500_contracts.py`** (new): one-off diagnostic. `--quick` for 7-symbol sanity, full run for all 503. Fixed CSV header loader to recognize `Symbol` in addition to `Ticker`.
- **`CLAUDE.md`**: production-strategy table updated — OMR and RAMP both run under `homeguard-multi` (not the disabled `homeguard-omr`/`homeguard-ramp` units), and a note that `--strategy multi` currently runs only one strategy by priority (OMR > MP > RAMP), so the unit is pinned to `--strategy ramp` to avoid priority surprises.
